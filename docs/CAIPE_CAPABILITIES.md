## Other findings

- **Auth is real and on.** Keycloak realm `caipe`, OpenFGA, agentgateway (:4000 returns 401 without a token). The dynamic-agents API rejects requests without an `X-User-Context` header; they must come through the UI's API gateway. Our eval harness (Phase 5) has to go through the UI route with a real login, or a service account.
- **The `caipe` realm has no users** (`setup_notes.md` section 5, item 2). The three personas need to be created.
- **`DYNAMIC_AGENTS_ENABLED=false`** in `.env` (the UI feature flag), although the `dynamic-agents` profile and container are running. It needs to be on for the custom-agent UI.
- **Two services on the install are public**: `caipe.ponchotitlan.dev` and `auth.ponchotitlan.dev` through a Cloudflare tunnel. The admin console on the public host is not yet blocked (`setup_notes.md` section 5, item 1). Relevant for a live demo on stage.
- **Version mismatch.** Source is `1.3.0-rc.16`, images are `0.5.66`. Docs and code we read describe the source tree and may not match the running images in every detail. That is why rows 3, 4, 7 and 9 say "unverified live".
- **Missing tools on the host:** `make` and `gh`. The spec's Makefile targets need `make` installed (or a `justfile`/scripts fallback).
