# Decisions, fakes and deviations

One entry per fake, deviation or trade-off. On stage, say which parts are CAIPE and which are glue.

| ID | Phase | Decision | Why | Real version would be |
| --- | --- | --- | --- | --- |
| D-01 | 0 | The install already has `docker-compose.override.yaml` (MinIO image, Langfuse port, Cloudflare tunnel). Our additions go in a separate file in this repo, `docker-compose.demo.yaml`, passed with an extra `-f`. The original install files stay untouched. | The spec says to leave the install untouched, and the existing override carries the user's own fixes. | Same. |
| D-02 | 0 | Agents are MongoDB records created through the UI. We keep their definitions as YAML in `config/agents.yaml`, applied by a script. | Spec rule: nothing important may live only in a UI. | CAIPE reading agent definitions from files. Its README mentions deployment-owned YAML definitions; confirm in Phase 1. |
| D-03 | 0 | Persona boundaries use CAIPE's OpenFGA teams for KB and tool access instead of a custom policy proxy. `config/policy.yaml` stays as the readable source of truth and is applied to OpenFGA by a script. Open: whether the per-tool `can_call` relation is enforced for the cluster and GitHub tools. | CAIPE already has the mechanism; less custom code. | Same, if enforcement is confirmed in Phase 3. Otherwise a small policy proxy. |
| D-04 | 0 | Cluster agent is a small custom read-only MCP server (`get`, `logs`, `events`). | CAIPE 0.5.66 and the source tree ship no Kubernetes agent. | A shipped Kubernetes agent. |
| D-05 | 0 | Approval gate uses `interrupt_on` on `github.create_issue`. Pending check: the UI card must show title and body. | Native HITL primitive found. | Same. If the UI shows only approve/reject, add a thin approval page. |
| D-06 | 0 | Treat image tag `0.5.66` as the version of record, not source tag `1.3.0-rc.16`. | `IMAGE_TAG` is unset in the install's `.env`, so compose falls back to `0.5.66`. | Upgrade the images to match the source after the event, or pin `IMAGE_TAG` now. |
| D-07 | 0 | Use a `Makefile` as in the spec, but `make` must be installed first (`sudo apt install make`). | `make` is not on the host. | n/a |
| D-08 | app | checkout-api liveness (`/healthz`) fails once at least 10 payments have failed since process start and failures outnumber successes. Readiness (`/ready`) fails when over 50% of payments in the last 30 s failed. | A streak-based liveness never tripped: once readiness fails, the Service stops sending traffic, so the streak stalled. Cumulative counts restore the spec's "restarts above 0" symptom. | A real app would restart on a stuck worker pool or exhausted connections. |
| D-09 | app | One checkout-api codebase is built twice (`v1.3.2`, `v1.4.0`); the manifests differ in env, not code. | The spec's fault is a config change, so rollback restores the old timeout. | Separate releases. |
| D-10 | app | The read-only agent ServiceAccount and RBAC are not part of this step. | Out of scope for "sample app only"; belongs to Phase 1. | `incident-copilot-demo/app/k8s/rbac-agent-readonly.yaml` |
| D-11 | app | Public access to LedgerLite: the CAIPE `cloudflared` container is attached to the `kind` Docker network through `incident-copilot-demo/compose/docker-compose.cloudflared-kind.yaml` (apply with `scripts/expose.sh`, undo with `scripts/unexpose.sh`). Route `ledgerlite.ponchotitlan.dev` -> `http://ledgerlite-control-plane:30080` is set in the Cloudflare dashboard. | The install's own compose files stay untouched. | A dedicated tunnel for the demo, so CAIPE and Keycloak do not share one. |
| D-12 | 0 | CAIPE seeds its models from `config/caipe-app-config.yaml` (a copy of the install's `app-config.yaml` with the models list pinned to `gpt-4o`, provider `openai`). The install's `.env` points to it through `CAIPE_APP_CONFIG_FILE`. Backup of the original `.env`: `~/.env.backup-caipe-phase0`. | The shipped models were Bedrock only and no AWS credentials are configured. Keeping the file in this repo makes the model choice readable on stage. | A model entry per provider for the swap in beat 5 (provider B to be chosen). |
| D-13 | 0 | RESOLVED: `web-ingestor` was crash-looping (about 5,900 restarts) with 401s. Two stale settings in the install's `.env`: `INGESTOR_OIDC_CLIENT_SECRET` (old default, set to the rotated `caipe-platform` secret) and `INGESTOR_OIDC_ISSUER` (`http://localhost:7080/...` changed to `https://auth.ponchotitlan.dev/realms/caipe`). Containers `rag-server` and `web_ingestor` recreated. | The Cloudflare and credential-rotation changes made after setup were not applied to the ingestor path. Keycloak now issues the public issuer in every token. | n/a |
| D-14 | 0 | The install's `docker-compose.override.yaml` now sets `OIDC_ACCEPTED_AUDIENCES=caipe-platform` on `caipe-ui` (backup: `~/docker-compose.override.yaml.backup-caipe-phase0`). This is the value `docker-compose.dev.yaml` ships; the prod `caipe-ui` service omits it. | With dynamic agents on, the chat stream route re-validates the session access token as a bearer. That token has `aud=caipe-platform` (realm `profile` scope), and the UI accepted only `caipe-ui`, so every chat failed with 401 `BEARER_AUDIENCE_MISMATCH` ("No content was generated"). Signature and issuer checks are unchanged. | Fix the prod compose upstream, or add an audience mapper for `caipe-ui` in the realm. |
| D-15 | 0 | OPEN (cosmetic): the CAIPE UI shows "Degraded" because its "Dynamic Agents" health probe (image 0.5.66) fetches `${NEXTAUTH_URL}/api/dynamic-agents/health`, i.e. the public hostname. From inside the container that request hits Cloudflare Access and gets a 302 to the login page, so the payload is not `healthy`. Direct checks of `dynamic-agents` (`/health`, `/healthz`, `/readyz`) and the UI's internal route all pass, and chat works. Fix: in Cloudflare Zero Trust add an Access application for path `caipe.ponchotitlan.dev/api/dynamic-agents/health` with a Bypass policy (the route returns only `{"status":"healthy"}`). | `NEXTAUTH_URL` must stay public for login, and this UI version has no override for the probe origin. | A health probe that uses the internal service URL (the 1.3.0 source calls `dynamic-agents:8001/healthz` directly). |
